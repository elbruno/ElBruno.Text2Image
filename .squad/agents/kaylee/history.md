Applied to both MaiImage2Generator and Flux2Generator. Pattern: BuildErrorHint() method checks env var, returns appropriate message. - **Security fix: Health check MITM vulnerability (H-1 - HIGH):** Redesigned health checks to eliminate credential transmission over potentially unvalidated connections. Default behavior: local configuration validation only (checks endpoint + apiKey presence without network calls). Opt-in detailed checks: T2I_DETAILED_HEALTH_CHECKS=1 enables full endpoint reachability tests with credentials (debugging only). Applied to FoundryFlux2Adapter and FoundryMaiImage2Adapter. Pattern: Check env var before HTTP request, return healthy status if config present. Mitigates MITM risk during health check phase while maintaining backward compatibility and developer troubleshooting options.

- **Environment variable security patterns:** Established convention for security-sensitive feature flags: (1) T2I_DETAILED_ERRORS for error verbosity control, (2) T2I_DETAILED_HEALTH_CHECKS for network-based health validation. Both default to secure (production) mode, require explicit opt-in for detailed/insecure operations. Pattern aligns with existing T2I_ prefix used in EnvVarSecretStore. Future security features should follow this model: safe default, explicit opt-in for diagnostics.

## Phase 2: High-Priority Security Hardening (2026-04-22)

- **Plaintext secret warning improvements (H-2):** Enhanced warning visibility to prevent users from unknowingly storing secrets in plaintext. Implemented two-tier warning system: (1) Prominent startup warning (box format) displayed on every read operation when secrets.json exists, (2) Detailed write-time warning with file path and specific mitigation commands. Warnings recommend DPAPI on Windows (`t2i secrets set <provider> --store dpapi`) and environment variables for CI/CD. Changed from single warning per session to warning on every operation to ensure users cannot miss security implications. Pattern: make security warnings impossible to ignore, provide actionable remediation steps.

- **Path traversal validation (M-2):** Added Path.GetFullPath() validation to all file write operations to prevent directory traversal attacks. Validation pattern: (1) Resolve full path using Path.GetFullPath(), (2) Validate resolved path starts with expected base directory using StartsWith with OrdinalIgnoreCase, (3) Throw UnauthorizedAccessException if validation fails. Applied to: ImageGenerationResult.SaveAsync (validates against current directory for relative paths), InitCommand (validates against CWD), ConfigStore (validates against ConfigPaths.ConfigDirectory), PlainFileSecretStore (validates against ConfigDirectory), DpapiSecretStore (validates against LocalApplicationData\t2i). Prevents symlink attacks and ../ escapes. Pattern enables both relative paths (validated against CWD) and absolute paths (validated but allowed if explicitly provided).

- **HTTP response size limits (M-3):** Added 50MB response size limits to prevent OOM attacks from malicious or corrupted large responses. Implementation: (1) Check Content-Length header before reading body, (2) Throw InvalidOperationException if size exceeds MaxResponseSizeBytes (50MB), (3) Use HttpCompletionOption.ResponseHeadersRead for URL-based image downloads to read headers without body. Applied to both Flux2Generator and MaiImage2Generator for both API responses and image URL downloads. Pattern protects against memory exhaustion while allowing legitimate large images (50MB accommodates 8K images). Validates both initial API response and separate image download requests to cover all HTTP attack vectors.

- **Path validation learnings:** Path.GetFullPath() is critical for security—it resolves symlinks, normalizes separators, and canonicalizes paths. Always validate AFTER GetFullPath, never before. For user-provided paths, allow both relative (validate against CWD) and absolute (validate but don't restrict to CWD). For internal config/secret paths, validate against specific expected directories (ConfigDirectory, LocalApplicationData). Windows paths are case-insensitive; use StringComparison.OrdinalIgnoreCase for StartsWith checks.

- **Response size limit learnings:** Content-Length header is not always present (chunked encoding), but when available it provides early protection. 50MB limit balances security (prevents OOM) with functionality (allows 8K images which are ~30MB uncompressed). HttpCompletionOption.ResponseHeadersRead is essential for efficient header-only reads when downloading from URLs. Always validate both API response AND subsequent URL downloads—attackers could inject malicious URLs in API responses.
