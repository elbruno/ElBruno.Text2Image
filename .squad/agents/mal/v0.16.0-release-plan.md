## Strategic Decisions

### ✅ No New CLI Commands
**Rationale:** The user mentioned a potential "standalone upgrade command," but this is unnecessary:
- **Existing:** `dotnet tool update --global ElBruno.Text2Image.Cli` is the standard .NET tool upgrade path
- **Providers List:** `t2i providers` already shows health status (which implicitly indicates "are my configs current?")
- **Decision:** Document `dotnet tool update` clearly in README and skill file—don't reinvent .NET tooling conventions

### ✅ Skill File as Embedded Resource
**Current Implementation:** `SKILL.md` is embedded in CLI assembly via:
```xml
<EmbeddedResource Include="Skills\SKILL.md" LogicalName="ElBruno.Text2Image.Cli.Skills.SKILL.md" />
```
**Rationale:** Single source of truth. Skill content ships with the CLI—users can't have mismatched versions. `t2i init` always deploys the correct SKILL.md for the installed CLI version.

### ✅ Multi-Target Skill Deployment
**Current Implementation:** `t2i init --target all` (default) creates both:
- `.github/skills/t2i/SKILL.md` (GitHub Copilot)
- `.claude/skills/t2i/SKILL.md` (Claude Code)

**Edge Case Handling:**
- **Existing files:** Skip unless `--force` flag used (prevents accidental overwrites)
- **Missing directories:** Auto-create parent directories
- **Permissions:** Fail gracefully with clear error message

## Edge Cases & Risk Mitigation

### Edge Case 1: Embedded Resource Missing
**Scenario:** `InitCommand` can't load `SKILL.md` from assembly  
**Cause:** Build config issue, resource not embedded  
**Detection:** Unit test that loads embedded resource in CLI test project  
**Mitigation:** Validate `.csproj` includes `<EmbeddedResource>` tag, test in CI

### Edge Case 2: Git-Ignored Skill Directories
**Scenario:** User's `.gitignore` blocks `.github/skills/` or `.claude/skills/`  
**Impact:** Skill files not committed, other users can't benefit  
**Mitigation:** Documentation warns against ignoring these paths. Add to skill-integration.md best practices.

### Edge Case 3: Stale Skill Files After CLI Upgrade
**Scenario:** User upgrades CLI (0.15.0 → 0.16.0) but skill files in repo are stale (0.15.0)  
**Detection:** No automated detection—user must manually re-run `t2i init --force`  
**Mitigation:** Document in upgrade guide: "After upgrading, run `t2i init --force` to refresh skill files"

### Edge Case 4: Copilot Can't Find Skill File
**Scenario:** GitHub Copilot doesn't recognize `.github/skills/t2i/SKILL.md`  
**Causes:** Wrong path, file not committed, Copilot workspace not initialized  
**Mitigation:** Troubleshooting section in docs/skill-integration.md with diagnostics steps

### Edge Case 5: Multi-User Environments
**Scenario:** Multiple developers install different CLI versions, skill file conflicts  
**Best Practice:** Commit skill file from latest CLI version, ignore warnings from older versions  
**Documentation:** Explain versioning strategy in skill-integration.md
