## Work Summary

Implemented all provider adapters: local (CPU, CUDA, DirectML) and cloud (Foundry FLUX.2, Foundry MAI-Image-2). Created `ProviderRegistry` for adapter discovery and registration. Wired DI via `AddCliProviders()`.

## Deliverables

- `LocalCpuAdapter` — CPU-only StableDiffusion (default 512×512, 20 steps)
- `LocalCudaAdapter` — GPU-accelerated StableDiffusion with CUDA detection
- `LocalDirectMlAdapter` — DirectML backend (Windows-only)
- `FoundryFlux2Adapter` — Cloud FLUX.2-pro (default 512×512, 20 steps, endpoint rewrite)
- `FoundryMaiImage2Adapter` — Cloud MAI-Image-2 (default 1024×1024, min 768px, max 1M pixels)
- `ProviderRegistry` — adapter lookup by provider ID with availability checks
- `AddCliProviders()` — DI registration with keyed services for each adapter

## Key Decisions

1. **Provider defaults** — Sensible per-provider defaults (SD 1.5 local, FLUX.2-pro cloud, MAI-Image-2 dimensions)
2. **Endpoint rewriting** — MAI and FLUX.2 auto-convert `.openai.azure.com` → `.services.ai.azure.com`
3. **Health checks** — All adapters implement `CheckAsync()` for diagnostics (HTTP HEAD for cloud, model load for local)

## Handoff Status

✅ Complete. All five adapters production-ready. Local providers lazy-load models; cloud adapters ready for secret resolution.
